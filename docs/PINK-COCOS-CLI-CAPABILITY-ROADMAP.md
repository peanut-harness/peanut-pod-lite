# PinK / cocos-cli 能力拆解与 Peanut Pod 稳定性路线

> 核对日期：2026-10-27。本文是产品分析与后续规划依据，不是支持承诺、实施授权或实机验收回执。
> 当前实施边界仍以对应 OpenSpec change 为准；本文不开放任何版本或写能力。

## 1. 方向与范围

Pod 面向用户已有的 Cocos Creator 工程，保留跨版本适配、外部 AI 接入和创作工具工作流。旧工程兼容是产品重点，需要逐版本、逐操作兑现；不能用存在适配器或能力目录证明完整支持。

本路线优先处理三件事：完成现有版本的基础编辑链；兑现一个旧版最小编辑样板；统一在线场景与资产文件编辑的上下文和结果语义。随后按实际使用需求增加动画、粒子、材质与构建辅助能力。

不以工具数量、竞品命名或 MCP 协议作为功能完成度指标。不直接移植 cocos-cli 运行时，不新增第二套任务、审批、资产索引或写入执行器，不将当前分析扩大成全仓审计。

## 3. 三层职责与接入方式

| 层次 | PinK / cocos-cli | Pod 对应边界 |
| --- | --- | --- |
| 执行能力 | cocos-cli 提供工程、资源、Scene、Builder 等领域能力 | Engine + Creator 版本适配器，Lumen 处理受控资产编辑 |
| 编辑环境 | PinK 自有场景运行时、动画编辑器及领域服务 | Creator Host 管生命周期，Panel 消费稳定协议 |
| AI 入口 | 原生 `pink_*` 工具经 PinK API 或受限宿主桥接执行 | 外部 MCP 接入复用 capability registry、任务、审批和证据 |

当前安装包中的调用路径为 `Chat → pink_* → PinK API / 宿主桥接 → 领域服务 / cocos-cli`。文档与宿主代码均表明 PinK 启动的 CLI MCP endpoint 已停用；模块和兼容代码保留，独立 cocos-cli 及其他 MCP 服务不受该开关影响。不能将保留入口当作可用服务。

Pod 保留 `入口适配 → 统一能力契约 → 策略与任务 → 版本适配 → Creator / Lumen`。编辑器内 Hub 的 token 认证私有 action/NDJSON 路由不等于直接可用的完整标准 MCP Resources 服务；标准协议能力按既有提案补齐，不改变旧桥接入口。

| 参考图 | 8；添加、删除、选择、解绑、刷新、参数和显隐 | `reference.queryImage/setImage` | 当前已有路径先稳定；多图与解绑作为后续体验需求 |

| Builder | 14；构建、校验、任务查询/控制、阶段执行、模板、图集、Bundle 与压缩配置 | 平台/schema/默认配置查询和构建；短等待及 Web 新鲜产物验证已有基础 | 优先补长构建持续续查，再按需求补配置与阶段能力 |

103 个原生工具是 PinK 的当前工具清单；文档所列 CLI 104 项中 85 项有原生替代、19 项未覆盖。保留清单的 23 个入口随内置 endpoint 停用不再服务，不能把它们加到原生数量上宣称全部可用。

### 4.1 应优先借鉴的契约

1. **固定目标**：Chat/任务绑定场景 URL/UUID、runtimeId、generation；切标签不改变目标，重载后旧绑定失效。
2. **写前版本检查**：查询返回目标身份及适用 revision，确认后仍需在执行窗口重验；版本变化重新查询，不沿用旧确认。
3. **草稿所有权**：文件更新、在线编辑、人工草稿和动画会话不能互相隐式接管。无法证明可安全合并时停止写入。
4. **领域生命周期**：动画、构建、粒子分别定义进入/查询/动作/保存或终态；不用通用任意消息调用代替业务契约。
5. **真实完成语义**：构建受理不等于完成，取消受理不等于已停止；未知结果先查询，不自动重提或换入口执行。

PinK 的 Scene Undo 不等于资源文件回滚，其文档也不承诺跨窗口/面板/MCP 的原子事务。借鉴时必须保留这些限制。

| 3.0–3.5 | early-3x 适配与薄 Host | 均为空 | 实验支持，默认禁止写入；不继承 3.8 消息或序列化假设 |

每个 operation 的验收记录至少包含：Creator 精确版本、平台、Host/Core 候选及包摘要、operation、夹具身份、读/写路径、前置条件、原生读回、重开结果、日志增量、遗留资源、证据引用及未验证项。状态分别记录 `declared`、`implemented`、`runtime_verified` 和 `released`；状态不自动递进。实验、拒绝、不支持、未运行及无法确认必须可区分。

## 7. 稳定行为的设计要求

这些是后续设计和验收要求，不宣称当前已经全部实现。

### 7.1 一套执行内核，多种入口与版本适配

- MCP、面板和未来 CLI 入口共享 capability、schema、审批、writer、任务、幂等和 evidence；不在入口层另造业务写入器。
- 公共业务语义尽量稳定，消息名、AssetDB、序列化、进程和平台差异集中到对应版本适配器。
- 逐能力检测及精确版本实证优先；不以“存在同名 API”启用写入，不把高版本参数直接下发旧版。
- Lite 不导入 Pro，缺少订阅或 Pro 不能阻断基础编辑；订阅与本地写许可分别校验。

### 7.2 在线与资产文件编辑的衔接

| 情况 | 预期行为 | 必要验证 |
| --- | --- | --- |
| 用户切换选区或编辑器标签 | 任务仍绑定原工程和资源；不能解析时拒绝 | 准入、排队后执行和 postflight 均核对实际身份 |
| 场景重载、关闭或宿主重启 | 旧运行时引用失效，重新读取和绑定 | generation/session 变化不会把旧目标指到新场景 |
| 在线资源存在人工未保存草稿 | 不能直接用文件写入覆盖；提示处理草稿后重新规划 | 草稿、源文件及 revision 的冲突矩阵 |
| 文件编辑后同步编辑器 | 先完成受控提交、AssetDB settle 和身份检查，再按声明策略重载 | 文件/meta、AssetDB、编辑器实际状态一致 |
| 在线编辑需要保存 | 仅走已验证且明确开放的保存路径 | 不以盲调 save-scene、UI 提示或接口存在替代保存完成 |
| 人工修改发生在确认之后 | 执行前检查版本/身份，冲突后重新计划 | 不覆盖人工修改；不复用过期审批扩大写入 |

### 7.3 任务与失败的共同语义

- 分开报告可用、受理、执行中、已完成、失败、取消及无法确认；对外字段沿用或经批准扩展现有协议。
- 取消只有在原生停止和安全收尾得到证明后才算完成；等待超时不触发重复提交或强杀 Creator。
- 部分失败列出已变、未变及未知资源；恢复是有前置条件和审批的新任务，不能无条件反向覆盖。
- 输出校验同时覆盖合法空值、不支持、降级和畸形返回；错误提供安全字段路径，不泄露原始输入、token 或完整日志。
- 日志/截图辅助判断，不能单独证明资源正确、运行正确或全量回归通过。容量、分页、期限和证据保留均有界。

## 8. 分阶段工作与退出门槛

阶段是产品路线，不能直接当作实施任务包。每阶段开始前确认候选、owner、owned paths、依赖、原生证据和验收命令；未批准的后续阶段不自动启动。

| 阶段 | 交付内容 | 退出门槛 | 不包含 |
| --- | --- | --- | --- |
| R0：当前基线稳定 | 当前 3.8 最小编辑产品链；A1 具体输出、A2 长构建续查 | 安装/重开、定位、修改、提交、引用和日志检查具有同候选证据；超过 30 秒构建可续查且原生提交一次 | 声称六条产品主线已完成；新增烘焙功能 |
| R1：旧版样板 | 单一精确 2.4 版本的高频资源、Prefab、节点、组件和引用绑定链 | 每个选定操作原生读回并重开验证；不支持项有稳定原因；未通过项不开写 | 全 2.4/全 3.x 支持承诺；顺带迁移用户工程 |
| R2：编辑上下文一致 | 显式工程/场景身份、在线与文件模式、草稿冲突和重载规则 | 切标签、人工修改、重载、断线与重启不误写；现有成功路径保持兼容 | 新建并行内核；把内存 Undo 当文件事务 |
| R3：领域能力完善 | 按任务价值规划动画会话、粒子实时、材质入口、构建辅助 | 每项有查询、动作、原生读回、适用保存/终态和失败用例 | 根据工具数强行补齐所有竞品接口 |
| R4：后续专业能力 | 反射/光照烘焙、多参考图及其他专项 | 先证明用户任务需要和版本接口可用，再单独规划成本与验收 | 把内部导出或静态类型当已开放功能 |

R1 的实验不得污染 R0 基线；R2 中经证明确属基础编辑必需的保护应提前处理，不能以阶段排序为由跳过。MCP Resources 可按接入需求安排；它提高发现和读取体验，不代替业务稳定性。

### 8.1 与当前 OpenSpec 的关系

`align-editor-mcp-capabilities-with-pink` 仍只承载 A1 输出契约、A2 长构建、A3 粒子、A4 反射探针、A5 Resources 五项；当前任务 DAG 与全部验收保持，不因本文将 A4 描述为后续产品优先级就删除 A4、勾选任务或降低完成门槛。

产品建议是先交付 A1/A2 的可靠基础，再决定旧版样板、编辑上下文与新增领域能力的排期。若要将 A1/A2 独立发布或暂停/拆出 A4，需先协调修订该 change 的 proposal、specs、design、tasks 和验收边界；修订前不能以部分通过宣称整个 change 完成。R1/R2/动画等当前未纳入的工作另行形成提案。

## 9. 可复用的最小验收用例

| 用例 | 核心检查 | 失败/边界检查 |
| --- | --- | --- |

| Prefab 节点与组件编辑 | 创建/修改/删除、属性原生读回、保存和不同会话重开 | 必需组件、原生不支持字段、依赖引用、人工草稿保护 |
| 批量文件/结构修改 | 全批准备、提交窗口重验、逐项结果和证据 | 中途失败、摘要变化、撤销、超量和符号链接/路径逃逸 |
| 构建长任务 | 超过短等待后续查同任务、原生终态、新鲜非空产物 | 重复请求、查询失联、陈旧产物、跨 owner 查询、取消不支持 |
| 编辑上下文 | 明确目标、切标签保持目标、重载使旧绑定失效 | 人工修改、工程关闭、断线/宿主重启后旧引用不得继续写 |
| 动画/粒子等实时操作 | 显式组件、时间/动作读回、实时与保存状态分开 | 选区竞态、错误组件、非法速度/帧、其他会话草稿 |
| 恢复与连续使用 | 失败后重新查询真实工程状态、可恢复项执行受控恢复 | 不覆盖后续人工修改、不强杀进程、不自动重放未知写入 |
