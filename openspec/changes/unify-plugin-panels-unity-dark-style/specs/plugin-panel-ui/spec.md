# Spec Delta

## Purpose

为 Peanut Pod 中已有的独立插件面板定义一致、可读且适应 Cocos Creator 窗口尺寸的用户界面行为，让用户在不同插件间获得连贯的视觉体验，并能在较小或较大的停靠面板中继续完成操作。

## ADDED Requirements

### Requirement: 插件面板共享视觉语言

所有现有插件面板 SHALL 使用一致的深灰中性色视觉语言、清楚的文字层级、紧凑间距及可辨识的交互状态；颜色和边框不得降低内容与控件的可读性。

#### Scenario: 在不同插件间切换
- **WHEN** 用户打开 Peanut Pod 中任一现有插件面板
- **THEN** 页面背景、内容表面、分隔线、文字层级、控件和焦点状态呈现一致的视觉规则

### Requirement: 面板适配宿主可用空间

插件面板 SHALL 根据宿主当前提供的视口宽度和高度布局，不得依赖固定页面宽度或高度；尺寸变化后主要内容 SHALL 保持可见、可操作，且不产生页面级横向溢出。

#### Scenario: 宿主缩小面板
- **WHEN** Cocos Creator 停靠面板变窄或变矮
- **THEN** 侧栏、工具栏、表单和工作区按剩余空间收缩或重排，内容继续可达且控件不互相覆盖

#### Scenario: 宿主扩大面板
- **WHEN** Cocos Creator 停靠面板变宽或变高
- **THEN** 工作区利用新增的可用空间，不出现由固定最大页面宽高导致的大面积无效留白

### Requirement: 内容滚动保持在工作区

当内容超过可用高度时，插件面板 SHALL 在对应列表、表单或预览区域内滚动，并保留必要的标题和主要操作入口。

#### Scenario: 窄高视口包含长内容
- **WHEN** 列表、配置项或日志内容超出面板可用高度
- **THEN** 用户可在对应内容区域滚动查看全部内容，面板外层不截断操作入口

### Requirement: 现有插件行为保持可用

视觉与布局调整 SHALL 保留每个面板已有的输入、选择、生成、加载、保存、导入/导出和宿主通信行为。

#### Scenario: 使用重排后的插件控件
- **WHEN** 用户在任一调整后的插件面板执行原有操作
- **THEN** 操作仍触发原有处理流程并显示其状态或结果

### Requirement: 宿主装配受验证的可选原生能力

Creator Lite Host SHALL 从自己的发行包装配已签名的可选 Canvas 能力；签名与文件摘要校验不得跳过。能力来源 SHALL 通过显式打包配置指定，载荷 SHALL 计入 Host 发行摘要；未配置时 Lite SHALL 保持可用。

#### Scenario: 安装需要 Canvas 的插件
- **WHEN** 当前宿主包含适配平台且通过签名和摘要校验的 Canvas 能力
- **THEN** UI Prefab 与 SnowB 的安装不因缺少原生能力被拒绝，并按原插件约束检查其余依赖

#### Scenario: 原生能力缺失或损坏
- **WHEN** 当前宿主没有 Canvas 载荷，或载荷签名、文件摘要校验失败
- **THEN** 依赖 Canvas 的插件明确失败，Lite 与不依赖 Canvas 的插件继续可用

### Requirement: Lite 固定插件槽位独立运行

Lite Host SHALL 提供 Host A/B/C，并让 Host Controller 调用当前宿主的加载和关闭消息；每个槽位 SHALL 独立绑定活动插件并验证面板身份和安装路径。

#### Scenario: 单槽位加载与关闭
- **WHEN** A 和 B 分别装载活动插件，用户随后关闭 A
- **THEN** 仅 A 的绑定与面板关闭，B 的页面和请求继续可用

#### Scenario: 拒绝无效槽位与旧调用方
- **WHEN** 加载请求使用未知槽位、停用插件，或切换后的旧面板请求身份不匹配
- **THEN** 宿主明确拒绝请求，不改变其他槽位
