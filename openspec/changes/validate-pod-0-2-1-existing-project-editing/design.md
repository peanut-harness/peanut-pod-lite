# Design

## Context

`decouple-pod-from-cpm` 的 4.1 已在两份现有工程验证 0.2.0→0.2.1 升级、修复和 Host/Bridge 冒烟；4.2 代码已远端交付。当前矩阵仍有 12 条 `not_run`。`verify-managed-task-live.mts` 在 `assets/_peanut-managed-task-live/<runId>` 创建 Prefab/Scene 并验证任务并发、AssetDB 身份与 postflight，但脚本不会保存重开；`PodAcceptancePlan` 把该步骤标为 `save_reopen_entry_undefined`。版本化覆盖草稿各含 4,128/4,119 条 `pending`，不能从少量实测推断整份原生组件与代码矩阵通过。

## Goals / Non-Goals

**Goals:**

- 给 Creator 3.8.3、3.8.7 各建立一次可重算的 0.2.1 基础编辑运行链，逐阶段保存原始命令、产物身份、创建清单、重开后的独立读回和工程前后差异。
- 在运行前给每份工程明确备份、占用、精确写集和失败停止条件；失败时保留 `may_have_changed`，不盲目重放。
- 把最小实机链与全量 4,128/4,119 条覆盖草稿分开记账；仅在各自验收条件确实满足时更新矩阵结果。

**Non-Goals:**

- 不从已有工程证明空工程首装，不新建或重置工程，不触碰真实账号、Server、CPM 或稳定发行。
- 不用本阶段少数 Prefab/Scene 样本代替全部原生组件、字段和脚本组合的覆盖。

## Decisions

1. **冻结输入并串行运行。**以 4.1 实测的 Lite 0.2.1 Host/Core 归档和摘要为唯一候选；先读回现有安装态，身份不符立即停止。两份工程串行执行，每次启动前核对 Creator 进程、端口、可用空间和受保护资产摘要，并备份 Host、安装索引、包、资产命名空间、日志与缓存。既有工程不得被重置成“空工程”。
2. **把受管任务和重开读回分为两段。**第一段用现有受管任务路径在带 runId 的专用资产树创建测试资源，记录 Prefab/Scene、`.meta`、UUID、任务证据及增量日志。第二段在关闭本次 Creator 进程后重开同一工程，用独立只读命令核对主资源、AssetDB UUID、缺失引用扫描和日志，再比对备份。先给现有脚本补精确可控的输出与身份输入，重开读回使用单独入口；不要让脚本报告自行证明自己的重开结果。脚本/组件矩阵没有由这三份空资源覆盖，继续列为缺口。替代方案是将重开写入同一脚本，但它无法跨进程独立核对，故不用。
3. **为组件与代码矩阵保留完整分母。**基于现有版本化草稿列出运行时注册、策展组件、字段、TypeScript/JavaScript 单文件与跨文件依赖的精确子集及夹具闭包；每项必须有本版原生结果、读回与日志。尚无夹具或执行证据的条目保持 `pending`。Pod 基础编辑用例需要的保存重开链完成后，可记录其具体已证部分；完整主线 `passed` 还须独立满足矩阵剩余项，不通过降分母实现。
4. **证据和清理按创建清单。**每次写入限制在登记的 runId 资产树及 Creator 自有的 `temp/logs/library/profiles/settings` 变化；运行前记录原资产哈希，后验只移除明确由本次创建且已备份的资源。失败或出现未解释的新日志错误时停止该版本，留存原始证据和工程状态，再评估修复。

## Risks / Trade-offs

- [Creator 轮换日志或缓存] → 每次启动前备份、运行后快照与原始日志偏移；先前五份未备份日志缺失和 3.8.7 首次 `library` ENOENT 继续保留。
- [重开后 AssetDB 与磁盘身份不一致] → 标记本版失败或 `may_have_changed`，保留工程与日志，不自动重试或覆盖 `.meta`。
- [脚本样本远小于全量覆盖草稿] → 分别报告最小链与完整分母，缺项继续 `pending`/`not_run`。
- [工程被其它会话占用] → 无独占租约或新鲜占用快照时不启动 Creator、不写工程。

## Migration Plan

先完成规划检查点，再申请精确源码写集和两工程专用运行租约。源码与夹具在独立工作树验证通过后，以现有候选做两版串行实机运行；一版失败则保存证据并停止依赖步骤。结果审阅后才更新矩阵，按登记完成普通 Git 交付与独立远端回读。当前规划阶段没有运行或迁移副作用。
